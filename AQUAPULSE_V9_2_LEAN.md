## §5 Architecture
**One sentence.** AquaPulse turns a village's groundwater budget into a conformally calibrated weekly cap, allocates it fairly with a dignity floor, cross-checks self-reports against independent signals (electricity meter, satellite-implied crop water use), holds disputed water in escrow instead of cutting it, and issues a tamper-evident receipt nobody has to trust the operator for.
**Real vs simulated (must be visible in UI).** REAL: Sentinel-2 NDVI with scene ID+date (else `REPLAY(as-of)`), rainfall/ET₀ (Open-Meteo), GIBS context layers (display-only), CEA factors (confirmed version). REAL-if-found else REPLAY/SYNTH: block SOE/category, groundwater level series. SYNTH(seed): farmer reports R, meter hours E, well discharge Q, plot polygons (USER(file hash) if a CSV is loaded). Computation (Theis, cap, allocation, escrow, Merkle) is REAL on SYNTH+REAL inputs — say exactly that.
**Signal adapters.** `SignalSource<T>{id; kind: SYNTH|REPLAY|LIVE|USER; fetch(zone,week)→Series<T> with Prov}`: `SynthSource(seed)` default, `CsvSource(file)` browser-only, `ArtifactSource(url)`, later `DwlrSource`, `DiscomFeederSource`. Fusion never knows the source; UI always shows `kind`.
**Topology.** GitHub Actions (batch: `pipelines/stac_ndvi.py`, `et0_rain.py`, `stress_traj.py`) → committed artifacts `public/data/**`; Vercel static React/Vite/TS with TS math core in the browser and `snapshot.json` for first paint; backend per Gate G1. ### §6.4 Cap: bucket model + ACI + overdraw correction
```
h_t level above safe floor (m): DWLR series if found else SYNTH aquifer;  params S_y, A_z, ε (ASSUMPTION until cited)
Rch_t = ε·rain_t·A_z/1000 (m³/wk);   ĥ_{t+1}(Ext) = h_t + (Rch_t − Ext)/(S_y·A_z)
e_t = ĥ_t − h_t^obs (>0 = fell more than predicted);  m_t = Quantile_{1−α_t}(max(e,0) over last W=52 wks), level clipped to [0,1]
Cap_t = max(0, Rch_t + S_y·A_z·(h_t − m_t))
ω̂_t = EMA_θ(max(0, Ext^verified_{t−1}/Pool_{t−1} − 1)), θ=0.3; ω̂=0 when no verified extraction
Pool_t = min(Cap_t/(1+ω̂_t), B_REF)
ACI: err_t = 1 if e_t > m_t else 0;  α_{t+1} = α_t + γ(α_target − err_t), γ=0.02, α_target=0.10
SOE_t = ΣV_i/B_REF·100% (label only); tier: Safe ≤70 | Semi-critical (70,90] | Critical (90,100] | Over-exploited >100
```
`Ext` = verified extraction when available else reported (this is where verification enters the cap). Guarantee (Gibbs & Candès ACI): long-run average miscoverage → target without distributional assumptions; **not** per-week; about the forecast margin of this bucket model on this level series (with SYNTH aquifer it is a property of a simulation — UI says SYNTH). S1b fetches the paper, cites it, records the exact bound in `docs/ACSY.md`. D21: toy loop showed uncorrected verified-extraction cap overshoots; with correction mean pool and weeks-below-floor ≈ reports-only; margin absorbs bias (0.39 reports-only vs 0.14 verified at 60 % overdrawers). So claim only **attribution**; M4 measures and the UI shows whatever the stored trajectories show, including "no aggregate difference". `B_REF` = sourced weekly share of the CGWB extractable resource (In-GRES if found) or the panel's illustrative **130 h** for Zone-A; config only, never a literal in code. Endpoint `GET /api/cap/{zone}/{week}` → `{capM3, poolM3, boundHours, omegaHat, alpha, alphaTarget, realizedMiscoverage, margin, ess, modelHash, prov}`.

### §6.5 Allocation: weighted max-min water-filling (m³) + escrow
Demands d_i=V_i, weights w_i=L_i (optionally ×T_i^α_karma; **off by default**), floor f (m³/wk, config), pool P.
```
f_i = min(f,d_i); if Σf_i > P: alloc_i = P·f_i/Σf_i, raise FLOOR_INFEASIBLE (loud in UI)
else P'=P−Σf_i, d'_i=d_i−f_i; if Σd'_i ≤ P': alloc_i=f_i+d'_i
     else find θ: Σ min(d'_i, θ·w_i)=P' (bisection, 300 iters); alloc_i=f_i+min(d'_i,θ·w_i)
```
**Escrow (D19).** REVIEW farmer: `u_i=min(R_i,E_i)·Q_i; released_i=min(alloc_i,u_i); escrow_i=alloc_i−released_i` (held, not redistributed, not cut). Non-REVIEW: released=alloc, escrow=0. Committee decision (human; Merkle leaf + previous root): `DISMISSED` → escrow released; `CONFIRMED` → demand := u_i, week **re-run**, freed water redistributed by the same water-filling, receipts chain the revision; `TIMED_OUT` (`ESCROW_TIMEOUT_WEEKS=2`, ASSUMPTION) → released (fail-open). **No silent cut ever.** When water is scarce land share decides and nothing is escrowed (UI states: "water is scarce: land share decides; verification changes the label, the cap and the flags, not who gets water"). Vectors: pool 104 → escrow 0 all; pool 130 → Farmer C released 20.000, escrow 14.105.
Property tests (≥ 1,000 seeded cases each, hand-rolled generators, no new dependency): Σalloc = min(P,Σd) when floor feasible; alloc_i ≤ d_i; alloc_i ≥ min(f,d_i); permutation-invariant; monotone non-decreasing in P; = land-proportional when every demand exceeds its land share; released_i+escrow_i = alloc_i; escrow_i>0 only if REVIEW; no flag alone lowers alloc_i.

### §6.8 Merkle ledger
Field = UTF-8 of a canonical string; numbers `%.6f` (no exponent); each field prefixed by a **4-byte big-endian length**. Leaf = `SHA-256(0x00 || len(f1)||f1 || …)`. Node = `SHA-256(0x01 || left_32_raw || right_32_raw)` (raw digests, not hex). Odd count: **promote the unpaired node unchanged** (never duplicate).
